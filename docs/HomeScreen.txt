Назначение
HomeScreen — стартовый экран приложения, где пользователь либо выбирает локальную базу SQLite через файловый менеджер, либо открывает диалог подключения к удалённой БД (MySQL/PostgreSQL/MSSQL). Экран создает и управляет MDFileManager, всплывающим MDDialog с формой ConnectForm и переключает ScreenManager на экран "database" после успешного выбора/подключения.

Публичные атрибуты
dialog: MDDialog | None — лениво создаваемый диалог удалённого подключения. Хранится между вызовами, чтобы не собирать виджеты заново.
_connect_form: ConnectForm | None — инстанс формы внутри диалога. Создаётся один раз.
fm: MDFileManager — файловый менеджер KivyMD. Создаётся в on_pre_enter при первом входе на экран. Не сериализуется и не добавляется в дерево KV, живёт как поле Python. Колбэки: select_path=_on_pick, exit_manager=_on_close.

Значимые внешние зависимости:
app.config.BASE_DIR — стартовая директория для MDFileManager.
database.sqlite_connector.Database — обёртка для локальной SQLite, назначается в app.repo.
Экран с именем "database" должен существовать в ScreenManager (иначе переключение упадёт). В минимальной сборке он добавляется в MDApp.build() вместе с HomeScreen.

Жизненный цикл
on_pre_enter(self, *args)
При первом заходе на экран инициализирует MDFileManager, чтобы не плодить экземпляры. Дальнейшие входы пропускают создание благодаря hasattr(self, "fm"). Используйте это событие, если вам нужно отложенно подгружать тяжёлые зависимости.
Публичные методы (API для UI)

Локальная БД
open_file_manager(self)
Открывает MDFileManager в директории expanduser(BASE_DIR). Вызывается из кнопки «Open local DB» (см. пример KV ниже).
_on_pick(self, path: str)
Колбэк выбора файла. Жёстко валидирует расширение *.db; если не совпало — шлёт toast("Pick a *.db file") и остаётся на месте. Если ок — создаёт Database(path), кладёт инстанс в app.repo, закрывает FM и переключает экран на "database". Сайд-эффекты: меняет глобальное состояние приложения (репозиторий) и навигацию. Контракт: дальнейший экран должен уметь работать с app.repo.
_on_close(self, *args)
Закрывает MDFileManager. Обычно дергается по back/escape.

Удалённая БД
open_remote_dialog(self)
Ленивая сборка диалога подключения:
Внутри — ScrollView фиксированной высоты dp(360) с вертикальным контентом и полосой прокрутки по Y.
Контент — инстанс ConnectForm (кастомный BoxLayout из ui.widgets).
В подвале — две кнопки: Cancel (закрывает диалог) и Connect (дергает _connect_remote).
Заголовок — MDDialogHeadlineText(text="Connect to remote DB").
После сборки диалог переиспользуется.
_connect_remote(self, *_)
Считывает параметры формы (form.get_values()), извлекает engine и — временно — ничего не делает, кроме валидации движка и переключения на "database". Ветка для MySQL/PostgreSQL/MSSQL помечена pass — требуется дописать адаптер по интерфейсу репозитория и назначить его в app.repo. Если движок не поддержан — toast("Unsupported engine"). Важно: сейчас метод не устанавливает соединение; это заглушка.

Служебное
_toast(self, text) — обёртка над kivymd.toast.toast. Используется для коротких ошибок/подсказок.
Виджеты и составные компоненты, с которыми работает HomeScreen
MDFileManager (KivyMD)
Создаётся в рантайме в on_pre_enter.

Колбэки:
select_path=self._on_pick — обработка выбора файла.
exit_manager=self._on_close — закрытие менеджера.
Точка входа: self.fm.show(start_dir).
Использование строго для локального выбора SQLite-файла.

Диалог удалённого подключения (MDDialog)
Собирается из следующих частей:
MDDialogHeadlineText — заголовок "Connect to remote DB".
MDDialogContentContainer — оборачивает ScrollView с формой ConnectForm.
MDDialogButtonContainer — Cancel (style="text", on_release=dismiss) и Connect (style="text", on_release=_connect_remote), плюс Widget() — спейсер.
Диалог создаётся один раз и дальше повторно открывается.
ConnectForm (кастомный BoxLayout)

Компонент формы для ввода параметров удалённого подключения.
Свойства и API:
engine: StringProperty — текущий движок ("MySQL" по умолчанию).
ssl: BooleanProperty — состояние переключателя SSL.
items: ListProperty — список пунктов для меню выбора движка с дефолтными портами.
open_menu() — открыть выпадающее меню движков.
get_values() -> dict — собрать словарь параметров: {"engine","host","port","database","user","password","ssl"}.
Внутри создаёт MDDropdownMenu над ids.engine_btn, автоматически подставляет порт при смене движка, опираясь на items и дефолты (3306/5432/1433). Требует соответствующих ids в KV: как минимум engine_btn, engine_btn_text, port, host, database, user, password, ssl.

Примечание: ConnectForm сам по себе не инициирует подключение — он только валидно собирает значения и управляет UI для выбора движка/порта. Подключение должен выполнять вызывающий код (HomeScreen._connect_remote).

Прочие используемые элементы
ScrollView — контейнер для формы в диалоге, с фиксированной высотой dp(360) и вертикальной прокруткой.
MDButton/MDButtonText — текстовые кнопки в футере диалога.
Widget — пустой наполнитель (расставляет кнопки в футере).
toast() — короткие сообщения об ошибках/валидации.

Интеграция с приложением
Минимальная инициализация экрана в приложении (MDApp):
Вариант с вашим модульным каркасом:
Приложение добавляет HomeScreen(name='home') в MDScreenManager и подгружает KV-файлы (KV_WIDGETS, KV_SCREENS, KV_APP). Экран "database" должен быть объявлен отдельно.
Навигация: после выбора файла или (пока фиктивного) удалённого коннекта экран переключается на "database". Убедитесь, что такой экран добавлен в ScreenManager, иначе получите KeyError/залипание навигации.

Контракты и ошибки (что важно знать интегратору)

Локальный выбор работает только для файлов *.db. Любой другой выбор — моментальный toast с требованием выбрать корректный файл. Логику расширьте, если у вас нет уверенности в расширениях.
open_remote_dialog() сейчас не подключает реальную БД — только собирает параметры и делает pass. Чтобы довести фичу:
реализуйте коннект к драйверу (pymysql/psycopg2/pyodbc и т. п.),
заверните подключение в «репозиторий» с единым интерфейсом,
присвойте app.repo = RemoteRepo(conn),
затем self.manager.current = "database". Комментарии-заглушки прямо в коде.
Экран "database" обязан уметь читать app.repo. Под минимальную SQLite-реализацию пример уже есть в проекте (Database и экраны работы с таблицами), но он лежит вне HomeScreen.

Краткий план расширения (без лирики)
В _connect_remote заменить pass на реальный коннект + адаптер репозитория, обработку ошибок драйвера (try/except) и валидацию params. 2) Добавить индикатор прогресса/блокировку диалога на время коннекта. 3) В ConnectForm.get_values() — базовую валидацию (пустые поля, диапазон порта) и подсветку невалидных полей через error/helper_text. 4) В open_file_manager — фильтрацию/маску по расширению и обработку отказа доступа к BASE_DIR.

Мини-FAQ по использованию

Как открыть локальную базу?
Вызвать root.open_file_manager() и ткнуть в *.db. Экран сам создаст Database(path), положит его в app.repo и переключится на "database".
Как подключиться к удалённой?
Сейчас — никак: UI есть, подключения нет. Вам нужно дописать _connect_remote. Параметры берите из ConnectForm.get_values().
Что сломается, если нет экрана "database"?
Переключение просто не состоится. Добавьте DatabaseScreen(name="database") (или ваш экран) в ScreenManager до вызовов open_file_manager()/open_remote_dialog().
