
SQLite Connector API Documentation
==========================

Класс `Database` представляет собой обертку над стандартным модулем `sqlite3` и предназначен для использования в мобильном приложении (например, на базе Kivy / KivyMD).

Основные задачи класса:
- централизованное открытие и закрытие соединения с SQLite-файлом;
- безопасная работа с именами таблиц и колонок;
- предоставление простого CRUD-API для экранов и сервисов приложения;
- логирование основных операций с базой данных.

1. Создание экземпляра
----------------------

Пример:

    db = Database(
        db_path: str | Path,
        *,
        check_same_thread: bool = True,
        pragmas: Mapping[str, Any] | None = None,
    )

Параметры:

- `db_path` — путь к уже существующему файлу базы данных SQLite.
  Если файл не найден, будет возбуждено исключение `FileNotFoundError`.
- `check_same_thread` — параметр, передаваемый в `sqlite3.connect`.
  По умолчанию экземпляр соединения нельзя использовать из разных потоков.
  Для приложений на Kivy рекомендуется использовать экземпляр `Database` только из одного потока
  (обычно основного потока UI) либо создавать отдельный экземпляр на поток.
- `pragmas` — словарь дополнительных PRAGMA-настроек.
  По умолчанию включаются:
  - `foreign_keys = ON`
  - `journal_mode = WAL`
  Через параметр `pragmas` можно переопределить или дополнить эти настройки.

При инициализации:
- соединение с базой данных открывается один раз;
- устанавливается `row_factory = sqlite3.Row`, благодаря чему методы возвращают строки в виде словарей (`dict`), а не кортежей;
- регистрируется конвертер для типа `DATE`, который пытается преобразовывать текстовые значения в `datetime.date` (при невозможности преобразования значение остается строкой).

2. Ограничения по именам таблиц и полей
---------------------------------------

Все методы, принимающие имена таблиц и колонок, используют валидацию по регулярному выражению:

    ^[A-Za-z_][A-Za-z0-9_]*$

Допустимы только идентификаторы, начинающиеся с латинской буквы или символа подчеркивания и далее
содержащие латинские буквы, цифры или символ подчеркивания.

Это означает, что запрещены:
- пробелы;
- дефисы;
- точки;
- символы национальных алфавитов (например, кириллица);
- прочие специальные символы.

Примеры корректных имен:
- `users`
- `user_profile`
- `patients`
- `Birthday`

Примеры некорректных имен:
- `user-profile`
- `user profile`
- `пациенты`
- `created_at+3`

При нарушении правил валидации возбуждается исключение:
- `ValueError("Incorrect table name: ...")` для имен таблиц;
- `ValueError("Incorrect column name: ...")` для имен колонок.

3. Общие принципы работы
------------------------

- Операции чтения (`fetch_rows`, `list_tables`, `describe_table`) не выполняют коммитов.
- Операции записи (`insert_row`, `update_rows`, `delete_rows`, `drop_table`) выполняют `commit()` внутри метода.
- Для более сложных сценариев работы с транзакциями предусмотрен контекстный менеджер `transaction()`.
  Важно учитывать, что при текущей реализации CRUD-методов коммиты уже выполняются внутри этих методов,
  поэтому использование `transaction()` поверх них не обеспечивает объединения нескольких операций в одну атомарную транзакцию.

4. Методы класса
----------------

4.1. list_tables() -> list[str]
-------------------------------

Пример:

    tables = db.list_tables()
    # ['patients', 'doctors', ...]

Метод возвращает список пользовательских таблиц в базе данных.
Системные таблицы с именами, начинающимися на `sqlite_`, отфильтрованы.

4.2. describe_table(table: str) -> list[dict[str, Any]]
-------------------------------------------------------

Пример:

    columns = db.describe_table("patients")
    # [
    #   {'cid': 0, 'name': 'id', 'type': 'INTEGER', 'notnull': 1, 'dflt_value': None, 'pk': 1},
    #   {'cid': 1, 'name': 'name', 'type': 'TEXT', ...},
    # ]

Параметры:
- `table` — имя таблицы, удовлетворяющее требованиям валидации.

Метод возвращает результат `PRAGMA table_info("<table>")` в виде списка словарей.
Удобен для динамического анализа структуры таблиц и генерации UI-форм.

4.3. fetch_rows(...) -> list[dict[str, Any]]
--------------------------------------------

Пример:

    rows = db.fetch_rows(
        "patients",
        columns=["id", "name", "Birthday"],
        where="age > ? AND Sex = ?",
        params=[18, "M"],
        order_by=["name"],
        limit=50,
        offset=0,
    )

Сигнатура:

    def fetch_rows(
        self,
        table: str,
        *,
        columns: Sequence[str] | None = None,
        where: str | None = None,
        params: Sequence[Any] | None = None,
        order_by: Sequence[str] | None = None,
        limit: int | None = None,
        offset: int | None = None,
    ) -> list[dict[str, Any]]:

Параметры:
- `table` — имя таблицы.
- `columns` — последовательность имен колонок или `None` для выборки `SELECT *`.
- `where` — строка условия без ключевого слова `WHERE`, например: `"age > ? AND Sex = ?"`.
- `params` — последовательность значений для позиционных плейсхолдеров `?` в выражении `where`.
- `order_by` — последовательность имен колонок для сортировки.
- `limit` — ограничение на количество возвращаемых строк (`LIMIT ?`).
- `offset` — смещение при выборке (`OFFSET ?`).

Параметр `params` поддерживает только последовательности (`list`, `tuple` и т. п.).
Словари в качестве `params` для данного метода не используются.

Метод возвращает список строк в виде словарей: `{"id": 1, "name": "John", ...}`.

4.4. insert_row(table: str, data: Mapping[str, Any]) -> int
------------------------------------------------------------

Пример:

    new_id = db.insert_row(
        "patients",
        {"name": "John Doe", "Birthday": "2000-01-01", "Sex": "M"},
    )

Параметры:
- `table` — имя таблицы.
- `data` — словарь вида `{"column": value, ...}`.

Метод:
- формирует SQL-запрос `INSERT INTO "table" (col1, col2, ...) VALUES (?, ?, ...)`;
- выполняет вставку данных;
- вызывает `commit()`.

Возвращаемое значение:
- идентификатор вставленной записи (`lastrowid`), если в таблице используется `INTEGER PRIMARY KEY`.

Если `data` пуст, возбуждается исключение `ValueError("insert_row: data пустое")`.

4.5. update_rows(table, data, where, params) -> int
----------------------------------------------------

Пример:

    count = db.update_rows(
        "patients",
        data={"name": "Alex Doe"},
        where="id = ?",
        params=[patient_id],
    )

Сигнатура:

    def update_rows(
        self,
        table: str,
        data: Mapping[str, Any],
        *,
        where: str,
        params: Sequence[Any],
    ) -> int:

Параметры:
- `table` — имя таблицы.
- `data` — словарь вида `{"column": new_value, ...}`.
- `where` — строка условия без ключевого слова `WHERE`, например `"id = ?"`.
- `params` — последовательность значений для плейсхолдеров `?` в `where`.

Метод:
- формирует SQL-запрос вида `UPDATE "table" SET col1 = ?, col2 = ? WHERE ...`;
- подставляет сначала значения из `data`, затем значения из `params`;
- выполняет `commit()`.

Возвращаемое значение:
- количество измененных строк.

Если `data` пуст, возбуждается исключение `ValueError("update_rows: data пустое")`.

4.6. delete_rows(table, where, params) -> int
---------------------------------------------

Пример с позиционными параметрами:

    deleted = db.delete_rows(
        "patients",
        where="id = ?",
        params=[patient_id],
    )

Пример с именованными параметрами:

    deleted = db.delete_rows(
        "patients",
        where="id = :id",
        params={"id": patient_id},
    )

Сигнатура:

    def delete_rows(
        self,
        table: str,
        *,
        where: str,
        params: Sequence[Any] | Mapping[str, Any],
    ) -> int:

Параметры:
- `table` — имя таблицы.
- `where` — строка условия без ключевого слова `WHERE`.
- `params` — либо последовательность (для позиционных плейсхолдеров `?`), либо словарь (для именованных плейсхолдеров `:name`).

Метод генерирует запрос `DELETE FROM "table" WHERE <where>`, выполняет его и вызывает `commit()`.

Возвращаемое значение:
- количество удаленных строк.

4.7. drop_table(table: str) -> None
-----------------------------------

Пример:

    db.drop_table("patients_backup")

Параметры:
- `table` — имя таблицы.

Метод формирует и выполняет запрос `DROP TABLE IF EXISTS "table"` и выполняет `commit()`.

4.8. transaction(): контекстный менеджер для транзакций
--------------------------------------------------------

Пример:

    with db.transaction():
        db.insert_row("patients", {...})
        db.insert_row("patients", {...})
        ...

Сигнатура:

    @contextmanager
    def transaction(self):
        ...

Поведение:
- в начале контекстного блока фиксируется начало транзакции (логирование);
- при возникновении исключения внутри блока:
  - выполняется `rollback()`;
  - исключение пробрасывается дальше;
- при успешном завершении блока выполняется `commit()`.

Следует учитывать, что текущие методы `insert_row`, `update_rows`, `delete_rows` и `drop_table`
выполняют `commit()` самостоятельно. Поэтому использование `transaction()` поверх них не обеспечивает
формирования единой атомарной транзакции на несколько операций. Для построения сложных транзакций
может потребоваться дополнительный слой абстракции или отдельные методы без автоматического коммита.

4.9. commit(), rollback(), close()
----------------------------------

Примеры:

    db.commit()    # Явный коммит (обычно не требуется при использовании CRUD-методов)
    db.rollback()  # Явный откат
    db.close()     # Явное закрытие соединения

Рекомендуемый паттерн для приложений на Kivy:

- создавать экземпляр `Database` на уровне приложения или экрана;
- использовать методы чтения и записи в отдельных слоях (репозитории, сервисы, модели);
- при закрытии экрана или приложения явно вызывать `db.close()`.

Метод `__del__` также пытается закрыть соединение при уничтожении экземпляра, однако полагаться
исключительно на деструктор не рекомендуется: явный вызов `close()` дает более предсказуемое поведение.
